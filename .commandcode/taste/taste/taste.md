# Taste
- Prefers plain, quick-to-grasp copy — avoids vague jargon and long descriptions; the point should be obvious at a glance, and labels should be trimmed to the essential value (e.g. just "46 members", not "Whole office · 46 members"). Confidence: 0.7
- Does not want specific performance/speed promises in product copy ("matched in 0.8s") unless the product can actually guarantee them; keep claims honest and remove figures he can't stand behind. Confidence: 0.75
- Prefers realistic, believable numbers in UI/demo content over inflated stats (e.g., "5–10 photos requested", not "312 joined, 40 requests"). Confidence: 0.65
- Expects new sections to visually match the existing page — reuse the established gradient/color/button language (e.g., hero gradients, existing button classes) instead of inventing a separate style. Brand palette is blue `#0053FF` + amber `#FCAA02` on light/white backgrounds; components that drift from the hero's look should be brought back in line with it. When a section is restyled, expects the established bento-card treatment to be carried over to the other sections too (e.g. "do what we did with the bento grid for How It Works"). Confidence: 0.85
- Wants UI showcases to animate rather than be static mockups, but the demo must loop on its own — do not add replay/play buttons that the user has to press to see it run again. Confidence: 0.8
- Rejects schematic/vector "AI-sloppy" demo visuals (SVG avatar heads, degree gauges, angle readouts, icon checklists); wants real photography of an actual person, with the action shown by the motion itself rather than spelled out in labels. Confidence: 0.7
- When asking for a styling change on an inner element (e.g. a bento tile/div), expects the edit to stay scoped there — no new ambient washes, gradient ring wrappers, or decorative borders added around the outer section/container, and no restyling/rewriting of the section heading or intro copy (keep existing headline text and markup, including any highlight styling). Confidence: 0.85
- Expects a section's content to stay true to its stated purpose — a section framed as "the problem" should only state the problems, with feature/solution demo widgets (toggles, share-link mocks, guest lists) removed from it. Confidence: 0.6
- Expects demo/mock UI content to be internally consistent: a group labelled one event must use photos of that event, an "N found" result must highlight N items, and the surrounding counts should add up (total − yours = the remainder). The same fictional people should carry across related tiles — names invented in one tile must reappear in the other, with matching initials ("Rahul Kumar" → "RK"). Confidence: 0.7
- Checks that placeholder/stock imagery actually depicts what the UI claims — e.g. photos marked as "faces found" must contain visible human faces, and a "look left"/"look right" demo cue must show a head actually turned that way — and asks for imagery themed to the specific event type (college fest, festival, corporate meeting) rather than generic party shots. Confidence: 0.7
- Prefers real stock portraits over initials-only placeholder avatars in people lists, matched to the person's inferred gender. Confidence: 0.6
- Prefers blue (not amber/yellow) for technical scan/detection effects — it reads as more precise — and expects such an effect to sweep the whole subject area (e.g. the full photo, with a frame around the complete face), not just the tightly-cropped region. Confidence: 0.6
- Wants a calm, minimal design register overall — components should feel restrained and "less interactive" (fewer busy effects/hyperactive widgets) rather than flashy, so every section reads like the quiet hero. Confidence: 0.6
- Dislikes saturated filled tiles/cards — blue gradients, amber/yellow gradients, and dark navy gradients alike: keep pushing until every card in a section uses the same neutral light-grey surface (subtle slate ring, slate text and nested panels retuned for contrast). When he says "make the grids light grey," apply it uniformly across all cards in that section rather than only the one he circled. Confidence: 0.8
- When he points at one specific instance of a shared component (e.g. "this button in the CTA section"), change only that instance — do not propagate the restyle to other uses of the same component (navbar/header button, other CTAs) without asking. Confidence: 0.75
- For end-user-facing pages (e.g. the attendee/share portal), wants only the essential info — event name, host, photo count, attendee count — with technical stat badges ("14 photos indexed, 61 faces"), status/tag chips, and architecture/marketing explainer blocks ("privacy-first architecture") removed entirely. Collapse a count into plain text ("14 photos") instead of adding a badge. Confidence: 0.7
- Wants tuning parameters that affect result quality (e.g. face-match sensitivity) to be host-only: hidden from attendees, settable from the host/manage view, and rejected by the backend for anyone else. Defaults should be sane and neutral rather than aggressively tuned. Confidence: 0.7
- Simplifying a page's presentation must not delete its working functional capability: when the attendee-portal cleanup dropped multi-angle (front/left/right) selfie capture, he demanded it be restored — the cues and multi-shot flow belong inside the existing flow, not as new screens/"other UI" bolted on. Confidence: 0.65
- Wants section backgrounds to continue the rest of the page — no tinted/grey band or divider behind a section — and section headers as a single centered title with no supporting description paragraph. Confidence: 0.6
